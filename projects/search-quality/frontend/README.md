# 搜索质量评测前端

从仓库根目录运行：

```bash
cd projects/search-quality
python3 -m frontend
```

打开 **http://127.0.0.1:8765**。仅依赖 Python 3.9+ 标准库，无需 Node、npm 或安装前端依赖。
前端文件放在 `frontend/static/`，HTTP 服务和后台评测管理放在 `frontend/`。

## 页面使用

### 排序指标与检索配置对比

评测结果下方的“排序效果”展示 NDCG@10、MRR@10、Success@1/3/10。
第二层 URL 打分逻辑不变；第三层计算位于 `quality_metrics/ranking.py`，不调用模型。
每个模型/方案/重复次数/检索运行分别统计；运行中显示临时覆盖，结束后自动保存
`frontend-runs/<id>/ranking_metrics.json`，历史记录首次查看时也会生成。支持导出逐 query 指标。

- 成功阈值固定为 3：完整正确且无未化解冲突。2 分不算 Success；MRR 只取首个 3 分的排名倒数，前十无 3 分为 0。
- NDCG 使用收益 `-1/0/1/2/3 → 0/0/1/3/7`，折扣 `1/log2(rank+1)`，先按 query 计算再等权平均。
  单次运行的理想排序取自自身返回的前十条，明确标为“列表内”；IDCG=0 时 NDCG=0。
- 保留原始 rank；不足十条补空位。重复 URL 只在首次出现时计收益，后续位置保留但收益为 0。
  前十条任一评分缺失、失败、无效或模拟，整个 query 排除。采集成功但无结果的 query 计 0，采集失败不当作空结果。
- 选择已结束的基准运行，再点击“对比排序效果”，使用双方 query ID 和 query 内容一致、且两边前十条评分完整的交集。
  每个 query 的理想排序取双方前十条 URL 并集去重后的共同候选池，不是全网理想结果。
- 同 URL、相同证据内容的分数冲突统一使用**所选基准运行的首次出现分数**；基准未包含的 URL 使用当前运行首次分数。
  五个对比指标均按这套固定分数重算，并展示冲突数量；不覆盖原始评分、不自动重评、不声称基准是真值。
  同 URL 内容变化（包括同一运行内重复 URL 内容不同）、需求解析不同的 query 排除。换基准会改变参考评分，报告包含两次运行 ID。
- 不同评分模型、模型参数、Prompt、方案、模式不能直接配对；多次重复评测可在分组下拉框选择。
  同分不代表正确，建议最终用人工核验后的固定 qrels；对比表显示实际分母与各排除原因，不能将缺失评分视为 0。

读取接口：`GET /api/jobs/<id>/ranking`（汇总）、
`GET /api/jobs/<id>/ranking-comparison?baseline=<id>&current_group=<group>&baseline_group=<group>`（含逐 query 对照）；
单分组时 group 参数可省略。只有本机只读分析，不额外发送 API 请求。

验证：`python3 -m unittest discover -s tests`；数学与数据边界用例见 `tests/test_ranking.py`。
定义参考：[IR 教材 NDCG](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)、
[ir-measures](https://ir-measur.es/en/latest/measures.html)。

BrowseComp / FRAMES / SimpleQA 的“含标题摘要”案例集按 3 个数据集 × 5 个检索配置分别导入，
例如 `BrowseComp · bge30（BGE Top30 重排）`。每次选一份数据集、一个评分模型进行可回答性评测。
`summary` 完整映射为 `snippet`，原始排名、重复 URL 和空结果查询保留。
`reply` 与标准答案只保存在冻结的原始 JSON 中，不作为逐 URL 人工标签，也不传给评分模型。
采集时间未知，使用“暂不设置”时间策略；这些数据支持 API 内容模式，不作为完整网页快照。

可使用以下命令从新版案例目录重新生成 15 份标准化数据集（输出目录必须不存在）：


输出包含 `inputs/` 下的转换文件、`datasets/` 下的 15 份数据集，以及记录来源哈希、数量和路径的
`datasets_index.json`。标准化目录可通过前端“加载数据集”登记，登记后保留在选择列表中。

运行记录和结果概览显示整次评测耗时、开始与结束时间。运行时每秒更新，结束后固定；
耗时从创建评测开始，包含需求解析、评分、等待、重试和报告生成，不累加并行请求的耗时。

### Ateve-Jev 原生评分

评分模型中新增 `Ateve-Jev · TokenDance`，默认型号 `ateve-jev-v1`。
在项目 `.env` 的 `ATEVE_JEV_API_KEY` 填写 TokenDance API Key，保存并刷新页面即可选择。
配置见 `examples/evaluation.ateve-jev.json`；现有模型配置不变。

- 推理接口：`https://tokendance.space/gateway/typesafe/v1/systemone`，使用 Bearer 鉴权。
- 型号列表调用 `https://tokendance.space/gateway/v1/models`，只显示声明 `typesafe:systemone` 的型号。
- 一条 URL 一次 Choice 调用，候选为 `-1/0/1/2/3`；使用返回的 choice 作为整数评分，不对概率求平均或四舍五入。
- Jev 使用独立模板 `quality_eval/prompts/answerability_jev.json`（Jev · 可回答性 v1）。共同规则放入 `instructions`，五档完整定义放入 `criteria`，不附加生成式 JSON Schema、理由或引文要求。`state` 保留 Query 与本条证据，不读取人工分数或历史 Jev 标签，也不发送生成引文所需的 `evidence_catalog`。
- 前端选择 Jev 后，Prompt 编辑器和版本列表自动切换到 `answerability_jev`。编辑的是含 `type`、`instructions`、`criteria` 的 JSON；必须保留 `type=choice` 和五个非空档位定义。Jev 与其他评分模型的版本、草稿分别保存。模板预览展示空 `state` 的原生请求，历史任务展示调用时保存的完整请求。
- 命令行可用 `prompt_overrides.answerability_jev` 提供该 JSON 对象的字符串。专用 Prompt 的哈希包含共同规则与全部选项；修改任一档定义都会改变任务标识。已有历史请求不随新模板变化。
- v1 保留 −1/0/1/2/3 语义，明确 2 是完整正确答案伴随未化解冲突；去掉人物身份等任务中未被 Query 要求的固定必答项，标题本身含完整答案也可评 3。此版本尚未进行新的人工一致率校准。
- Jev 不生成文字理由或引文。结果详情展示原生 choice、probabilities、confidence，并明确这是结构化选择。置信度按接口原值保留，不冒充人工一致率。
- 原生输出使用 `systemone-choice-v1` 校验（五档、概率范围与和、所选档最高概率、置信度范围），不伪造 evidence 来通过生成式引用校验；其他模型继续使用原有校验。
- 请求体在调用时保存，实际 Prompt 查看器展示 `state / questions / model`；响应页保留原生返回字段与用量、耗时和失败信息，不保存鉴权头。
- 需求解析可继续关闭；开启时，可从其他已配置的生成式模型中选择解析型号，Jev 仅负责可回答性。其他维度暂不支持 Jev。
- 评分继续参与现有圆环图、人工校准、历史记录、重复评测与导出。默认并发 32、请求速率 16/s、最多 4 次网络尝试（首次 + 3 次重试），可在配置文件调整；账户限额以平台为准。

接口依据：[模型页面](https://tokendance.space/models/ateve-jev-v1)、[TokenDance 协议](https://tokendance.space/docs/protocol-typesafe-systemone)、[Choice 结构](https://docs.typesafe.ai/primitives/choice)。

### 失败原因检查与自动恢复

新建评测默认开启 `failure_recovery`，应用于需求解析和各评分方案。失败原因由本地错误码、响应结束原因及结构／证据校验确定，无需额外调用模型诊断。

| 失败情况 | 自动处理 |
| --- | --- |
| JSON 无法解析、字段／类型／枚举不合规 | 加入固定的格式纠正提示，重新生成并校验 |
| 引文为空、无法逐字匹配或引用路径不合规 | 提示仅引用当前输入中的原文，重新生成并校验 |
| 输出 token 截断 | 将该次调用的输出预算翻倍，最多到恢复配置上限；已达上限则停止 |
| 空响应、流式中断或不完整 | 退避后重试，保留收到的可见响应 |
| 认证、额度、参数、模型拒绝或输入缺失／超限 | 停止，保留失败原因 |
| HTTP 临时错误或网络异常 | 沿用现有网络层指数退避；耗尽后不由恢复层重新启动 |

配置位于运行冻结的 `config.json` 和 `examples/evaluation*.json`：

```json
"failure_recovery": {"enabled": true, "max_attempts": 3, "max_output_tokens": 32768}
```

`max_attempts` 包含首次调用，默认最多首次 + 两次自动恢复；每轮内部仍受模型原有 HTTP 尝试次数约束。例如模型 `max_attempts=2` 时，每任务最多 6 次 HTTP 尝试，并非保证都会发生。恢复等待使用相同的指数退避抖动参数及累计等待上限；所有轮次复用同一模型客户端的并发、速率和冷却控制。

`max_output_tokens` 只在截断后调整，不能超过配置上限；若初始预算已不低于该上限，不再增加。平台若不接受增加后的预算，保存参数错误并停止；不修改共享模型配置。Jev 原生 Choice 请求不追加生成式纠正文本，不调整其不支持的 token 参数。

有效低分和符合规则的弃权不会重试。多维任务或重复判定只有部分失败时，保留已校验的维度／记录，仅采纳失败部分的修复，并重新检查组合后的约束；冲突时保留原来的有效判断。

每轮请求前持久化登记，之后保存可见原始响应、失败原因、实际 Prompt 哈希及输出上限。中断后恢复会沿用已登记轮数；未取得响应的在途请求仍消耗一轮，计费情况标记未知。显式重评使用独立的 cycle，不覆盖上轮记录。恢复提示不改变五档标准、输入证据、模型或采样参数；它会改变实际请求的 Prompt，故单独留档。

结果概览显示首次失败、重试和恢复成功数量；“模型响应”可逐轮检查失败与成功响应。`evaluation/recovery/<task_id>/cycle-N/` 保存全部尝试，`evaluation/prompts/` 保存去重的实际提示词，导出保留 `auto_recovery`。统计包括各轮已知调用和 token 用量，未返回用量不视为免费。

没有恢复配置的历史冻结任务继续遵循原策略，查看或刷新页面不会调用 API、不会重评旧失败记录。 恢复接口默认仅继续未保存任务；明确提交 `POST /api/jobs/<id>/resume` 且正文为 `{"retry_failed":true}` 时，额外归档并重试已保存的 error／invalid_output／partial_output 记录，已有有效任务不重新采样；模型和评分配置不变。CLI 可在新配置中关闭 `enabled`；已有冻结运行的配置不能中途改变。所有本功能验证使用离线传输夹具，未执行真实模型评分。

### 接口重试与限流冷却

网络重试统一使用有上限的指数退避与 Equal Jitter 随机等待：默认三次重试分别等待
2–4、4–8、8–16 秒，随机错开发送时机；重试仍计入原有并发和每秒请求上限。
收到有效 `Retry-After` 时，等待至少达到服务端指定的秒数或 HTTP 日期，不能被退避上限截短。
429 和 503 会冷却**本批次同一模型客户端**尚未发送的请求；已经在途的请求不取消，其他模型客户端不受影响。
冷却结束后仍按速率逐个放行，等待中的请求会重新检查新的冷却期限，不在同一时刻集中补发。

Jev 已配置 `max_attempts: 4`；其他模型保持各自的尝试次数。共同策略支持以下模型级配置：

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| `retry_base_seconds` | 4 | 第一次退避的上界，实际在其一半到全部之间随机取值；后续上界翻倍 |
| `retry_max_seconds` | 60 | 指数退避上界，不截短 `Retry-After` |
| `retry_wait_budget_seconds` | 120 | 单条调用累计的发送前等待预算，包含速率排队、共享冷却和退避，不含网络请求执行和并发槽排队 |

如果下一次发送所需的等待超过剩余预算，停止该条任务并保存原因，不提前发送。
网络层只重试 HTTP 408/429/500/502/503/504 及连接失败、超时；认证、参数错误和拒绝不重试。输出截断和无效评分由下面的自动恢复处理。
重试保持原请求内容；网络超时可能发生在平台已处理请求之后，无法保证服务端只处理或计费一次。
网络层耗尽次数或等待预算后，输出恢复层不会重新开启网络重试。 非流式响应的 `IncompleteRead` 等 HTTP 读取中断同样进入网络层重试；HTTP 错误正文读取中断时仍保留原 HTTP 状态，不让单条连接中断退出整批评测。

“模型响应 → 响应详情 JSON”保存每次 HTTP 状态、`retry_after_seconds`、退避计划、
`wait_before_seconds` 实际等待、是否继续重试及停止原因。历史 429 也会显示“接口限流（429）”。
本次修改对新运行生效，不自动重跑既有失败记录；服务端持续限流时仍需调整并发或请求速率。

设计参考：[AWS 退避与抖动](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/)、
[Google 重试策略](https://docs.cloud.google.com/storage/docs/retry-strategy)、
[HTTP Retry-After 标准](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)。
选择 Equal Jitter 是为了保留最短冷却时间；不是照搬某个平台的默认参数，也不代表已测得 TokenDance 的配额。

1. 选择已有数据集，或点击“选择文件或目录…”浏览本机路径，也可以直接粘贴绝对路径，再点击“加载数据集”。
2. 当前工作台只评“可回答性 · 单维评分”，默认使用150条人工校准集。其他方案保留历史查看能力。
3. 单选一个评分接口，切换接口会自动取消之前的选择。页面会调用所选接口的模型列表，例如选择 DeepSeek 后调用 `/v1/models`。
   在“评分型号”下拉框选择用于 URL 评分的具体型号，每次评测仅使用一个评分模型，启动接口也会校验这一限制。
   “需求解析模型”可从所选接口返回的全部可用型号中独立选择，不受评分型号限制。
   刷新后原型号仍可用时保留选择。获取失败会显示原因，可点击“刷新”重试；
   选好具体评分型号后才能开始。
   “解析 query 需求”默认关闭；关闭后只禁用解析型号选择，仍获取并使用评分型号列表。
4. 选择查询数量、证据模式与重复次数。默认选择全部 query 和 API 返回内容。
5. 点击“开始评测”。开启需求解析时先冻结需求，再并行评分；关闭时直接评分。
6. 在评分明细中按 query、标题、URL、方案、模型、指标或状态筛选。点击一条结果查看理由、原文引证、输入文本和冻结需求。

页面顶部四项统一展示当前配置的待评测范围。查询按 query ID 排序选取，与实际运行一致；
结果数逐条统计所选查询的返回结果，保留重复 URL，不乘以模型、方案或重复次数。
卡片下方保留全量数据集的查询数和结果数。第三项展示所选结果关联的人工参考评分数，
第四项展示方案数和子指标数。
切换数据集或查询数量会重新校验并统计，不调用模型。读取失败时清空数字，可点击“重新统计”。
顶部预览与历史运行相互独立；实际运行的查询和结果数显示在“运行与结果概览”标题中。

## 查看评测 Prompt

配置区的 **Prompt 版本** 可以选择内置规则或已保存的自定义版本，点击“编辑 Prompt”直接修改 System 指令。
填写版本名后点击“保存新版本并应用”，再点击“开始评测”。建议先选择 1 条 query 验证输出与分数，再运行全量校准集。
开启独立需求解析后，还可以单独编辑需求解析 Prompt；版本按任务类型和需求解析模式绑定。
在实际 Prompt 查看器中，可以点击“以此为基础编辑”，将同类型、同模式的历史规则复制到编辑器。

编辑区不包含输出 Schema；平台会在 System 末尾自动附加固定 Schema，User 中的 Query、URL 与证据继续来自数据集。
规则不能为空，最多 50,000 个字符。模型仍须遵守输出字段、分数范围和证据校验约定。
每次保存创建一个新版本，不覆盖已有版本。选择“内置 Prompt”或旧版本即可切换；“载入内置规则”只更新编辑草稿，需保存后才应用。
未保存的草稿和版本选择保存在当前浏览器；关闭、刷新后可继续编辑。有草稿时开始评测会提示先保存或放弃，避免误用旧规则。
自定义版本持久化在数据根目录的 `.prompt-versions/`，包含规则、名称、创建时间和哈希，不包含 API Key。
运行启动时将选定规则复制到该运行 `config.json` 的 `prompt_overrides`，并将版本信息写入 `job.json` 的 `prompt_versions`。
评分和需求解析子进程读取这份冻结配置；历史任务继续保存实际 System/User 与 Prompt 哈希，后续编辑不影响旧运行。
保存、预览、复制均不调用模型；只有“开始评测”执行评分。

配置区的“查看实际 Prompt”打开当前选中的历史运行；未选择运行时打开最近一次运行。
“预览当前模板”另设入口，按勾选方案与需求解析开关，直接读取评分器当前组装的 Prompt。
新评测展示可回答性 Prompt；开启独立需求解析时同时展示需求解析 Prompt。历史任务仍可查看当时使用的其他方案。
运行概览的“查看实际 Prompt / 响应”和每项评分详情的“查看该项实际 Prompt”，读取任务中保存的历史
`request.system` 与 `request.payload`，不使用当前模板重建旧请求，也不发起模型调用。
正在执行的任务在检查点保存后可查看；失败、阻断和模拟任务均明确标注，未保存的旧 Prompt 不猜测补齐。

查看器默认按顺序并排展示完整 System 与 User 消息，窄屏上下排列。System 保留末尾的 JSON Schema，
User 保留协议层使用的原始紧凑 JSON；均仅自动换行，不改写内容。可分别复制原文，或复制完整消息 JSON。
也可单独查看 System、User、Schema 和模型响应。模板预览明确标注尚无具体 User 输入。
“API 请求体”根据历史运行的模型配置和该任务的 Prompt 快照，使用协议适配器还原模型、消息及生成参数；
明确标注为历史快照还原，而非网络抓包。不同协议使用各自请求结构；模拟任务没有外部请求体，
未调用的任务只展示准备输入，缺少历史配置时不使用当前配置代替。界面不返回 API Key 或请求鉴权头。

旧体系规则版本 1.1 对齐 evaluation 文档，单 URL 与重复性 Prompt 均不再允许
`unjudgeable` 质量标签。时效仅在没有时间需求时可“不适用”；内容不足按旧分档和布尔规则
保守裁决并说明证据限制。调用、输入或校验失败单独显示失败，不补造 0 分/false。
Google 的未知状态保持独立；旧运行查看当时快照，新建运行使用新版规则。
模拟模式的旧体系语义评分显示“仅模拟”，不生成真实质量分数。

## 从本机加载数据集

输入区支持本机任意可读取路径，浏览窗口可进入目录、返回上级、按名称过滤并翻页选择文件。
支持 `.sqlite` / `.sqlite3` / `.db`、`.json`、`.jsonl` / `.ndjson`、`.csv`。
文件结构沿用第一层适配器：SQLite 为 Ateve 采样数据库，JSON 为标准对象格式，CSV/JSONL
为扁平记录；自定义列名可在“导入选项”填写字段映射 JSON 文件的绝对路径。

SearchBench 导出的 Top10 人工/人工或 Jev 参考集 JSONL 可直接选择加载，无需字段映射。
适配器识别 `sample_id` / `query` / `reference_grade` / `reference_source`，保留每条 Query 的完整 rank 1–10。
参考分数与原始人工或 Jev 标签不一致、缺 rank、重复 rank、不同 Query 文本冲突时会阻止导入。
人工标签保存为 `answerability_human_v1`，Jev 保存为 `answerability_jev_v1`，两者独立于 API 证据。
目前页面的人工预览和人工一致率只统计人工标签；Jev 标签保存在 `reference_labels.jsonl`，不冒充人工。
原始文件中的 Golden Answer、人工理由和 Jev 详情均保留在 `raw/source.jsonl`，不进入模型输入。
这类导出没有搜索采集时间，请在“导入选项”将评估时间来源设为“暂不指定”；
也可以显式指定业务评估时间，不会自动拿网页发布时间或标注时间替代。

原始文件导入为 `../output/dataset-<文件名>-<随机编号>/` 下的独立快照，不修改源文件。
可自定义数据集名称，默认使用源文件名。评估时间默认取文件中最新的采集完成时间；
没有采集时间时，选择指定带时区的时间，或明确选择“暂不指定”。不会自动填入当前时间。
检查失败显示诊断与完整报告路径，保留原始快照和报告，不加入可评测数据集。

已有标准化目录（或其中的 `manifest.json`）通过校验后可以直接使用，无需再次导入。
外部目录记录保存在数据根目录的 `.frontend-datasets.json`，重启服务后仍可选择；
名称相同的不同路径保持独立。开始评测时重新校验文件哈希。目录缺失时不会启动评测。
页面显示源文件和实际评测目录；加载成功自动选中，刷新页面会记住最近选择。
加载和浏览仅进行本机文件操作，不调用评分模型。

## 可选的 query 需求解析

| 开关 | 执行流程 |
| --- | --- |
| 开启 | 独立解析每条 query，冻结需求说明，再交给所选评分模型评分 |
| 关闭 | 直接将原始 query 和结果证据交给评分模型，不调用解析模型，不生成共享需求说明 |

关闭后，两套方案仍可评分，评分模型在同一次评分输出中简短记录自己理解的需求。
这会省去独立解析调用，但不同模型、URL 或重复轮次的需求理解可能不同。
输出格式、引文真实性、必要条件和高分规则仍会校验；Page Quality 仍要求网页快照。
运行记录、评分 JSONL 和摘要用 `query_understanding=frozen/direct` 记录模式；
关闭时进度显示“需求解析已跳过”，不提供“需求说明”下载。
旧运行未记录此字段时按开启处理。每次新建运行的模式独立保存。

界面会显示进度、子指标分布、需求解析失败、无结果查询，以及同条件模型对比。
无效输出与无法判断不会被转换成 0 分；模拟结果明确标记，不纳入模型一致率。
分布是评分数量，不是质量准确率；本页面不计算第三层 Precision / Recall。
失败项显示具体原因，例如“证据路径错误”“引文不匹配”“接口连接失败”，概览按原因列出
受影响任务数和评分项数。旧运行的英文诊断也会转换为这些中文说明，原始导出文件保持不变。
新评分中可明确核实的证据路径笔误会自动修正，表格与详情标记“已修正引用”，并保留修正前后路径。
无法修正的引文问题按维度或 URL 隔离；共享结构及评分规则冲突仍严格阻止整个任务采纳。
评分失败不等于 URL 质量差；无法判断也不会变成 0 分。修正过程不调用模型，历史运行不会自动重算。
Google Page Quality 始终需要完整网页快照；当前数据只有 API 内容，因此该项会无法判断。

## API Key 和模型

服务直接读取项目根目录 `.env`，**无需手动 `source .env`**。
保存密钥后刷新页面，模型将显示“已配置”。这表示检测到配置，不代表已验证接口可用。
页面不接收或展示密钥。

模型来源：

- `examples/evaluation.models.template.json`：其他厂商与本地模型的配置。
- `examples/evaluation.deepseek.json`：DeepSeek 配置，覆盖模板中的同名 profile。
- `examples/evaluation.qianwen.json`：千问AI平台配置（`qianwen`），评分和需求解析均可使用。
- `examples/evaluation.mock.json`：本地模拟模型。

模型参数在这些文件中修改。当前前端的人工认可域名名单读取
`examples/evaluation.deepseek.json` 的 `approved_authority_domains`，所有所选模型共用此名单。
每次点击开始都会保存独立配置快照；后续修改不影响已经启动的运行。

评分与需求解析共用同一份型号列表：支持模型发现的 OpenAI 兼容接口和 Claude 使用 `/v1/models`，
已有版本或自定义路径的 `base_url` 会保留其路径；Gemini 使用原生 `/v1beta/models`。
支持分页返回的接口会继续读取后续页。Gemini 未声明支持文本生成的型号会展示但置灰。
本地模拟模型直接使用配置中的模拟型号，无网络请求。
勾选接口或点击任一“刷新”按钮都会重新获取列表，这一步不发起文本生成请求。
切换需求解析开关或选择具体型号不会重复查询接口列表。
API Key 只在后端用于鉴权，不传给浏览器。

开始评测时校验选中型号（可复用最近 5 分钟的成功列表）。
`job.json` 的 `scoring_model_ids` 按接口保存实际评分型号，`query_model_id` 保存解析型号。
`config.json` 将评分配置的 `model` 设为选中型号，保留该接口的其他参数。
如果解析与评分使用同一接口的不同型号，会为解析生成独立配置，二者互不覆盖。
新运行的记录、筛选器和评分明细显示实际型号；
评分 JSONL 的 `model_id`、摘要中的型号信息也会保留，`model_profile` 仍用于关联接口配置。
本次选择只作用于新的运行快照，不修改项目示例配置或过去运行。

### 千问AI平台

在项目根目录 `.env` 的 `QIANWEN_API_KEY` 单引号内填写从
[千问工作台](https://platform.qianwenai.com/home/api-keys) 获取的 API Key，保存后刷新页面，勾选“千问AI · qianwen”。
页面中分别选择评分型号和可选的需求解析型号，再开始评测。当前默认 `qwen3.8-flash`，
初始列表还包含 `qwen3.8-max`、`qwen3.7-max`、`qwen3.7-plus`、`qwen3.6-flash`、`qwen3.6-plus`。
可在 `examples/evaluation.qianwen.json` 的 `models.qianwen.catalog_models` 中补充平台支持的文本对话模型 ID；
修改后点击模型列表旁的“刷新”读取新配置。所选模型必须位于该列表。

调用地址为 `https://maas.qianwenaiapi.com/compatible-mode/v1/chat/completions`，使用 Bearer Key，
采用普通在线推理接口；不是 Batch API 或 Token Plan 专属地址。
平台官方说明其兼容接口不提供 `GET /models`，因此这里使用明确标注来源的本地型号列表，
不会将 401/404 猜测为“已获取模型”。“已配置”只表示已填写 Key；列表不代表已验证账户权限、模型开通状态或免费额度。
请按自己账户的免费额度选择型号；只希望使用免费额度时，可在平台开启“免费额度用完即停”。

千问配置启用 `stream: true`，兼容要求流式返回的思考模型；默认沿用模型自身的思考设置。
后端只拼接可见回答并记录用量，不保存内部推理文本。模型按 Prompt 中的 Schema 输出 JSON，再做本地校验；
不对所有型号强制发送 `response_format`，以避免不同模型能力不一致导致拒绝请求。
当前输出上限 16384 token。`timeout_seconds: 120` 限制连接及网络读取等待，
`stream_timeout_seconds: 600` 单独限制流式生成总时长（可配置 1–1800 秒），
避免模型仍持续输出思考数据时被原先的 120 秒总时限中断。修改只作用于新运行，已有运行保留配置快照。
中断、缺少结束标志、截断或拒绝均保持失败状态，页面按具体原因区分；部分回答及流式诊断可在“查看模型响应”中查看，
正文为空时自动展开响应 JSON，显示已接收事件数、正文字符数与本次生成时限。仅记录思考片段计数，不保存思考文本。
收到流式内容后不会因中断自动重新采样。

接入依据：[首次调用 API](https://platform.qianwenai.com/docs/developer-guides/getting-started/first-api-call)、
[不提供模型列表接口的说明](https://platform.qianwenai.com/docs/developer-guides/clients-and-developer-tools/deepseek-harness)、
[流式与思考模式](https://platform.qianwenai.com/docs/resources/faq-text-generation)。

## 文件与运行管理

默认读取 `../output/` 下各直接子目录中的第一层数据包。
新增输入文件可以直接在页面加载，也可以继续使用 `quality_input import` 导入该目录。
网页创建的运行保存到 `../output/frontend-runs/<运行编号>/`：

| 文件 / 目录 | 内容 |
| --- | --- |
| `job.json` | 前端运行状态与选项 |
| `config.json` | 本次使用的模型与方案配置，不含密钥 |
| `context.json` | 本次选中查询、API 结果与网页文本 |
| `specs/` | 冻结需求与解析调用记录 |
| `evaluation/` | URL 评分、任务检查点、模型对比 |
| `summary.json` | 评分阶段的运行摘要 |

页面内可导出评分 JSONL、需求说明、运行摘要和模型对比。
运行记录右侧的“删除”会移除该次运行及其评分结果；正在运行或排队的任务须先停止。
删除当前选中记录后自动展示下一条，删空后恢复空状态。删除后可点击“撤销”恢复最近一条记录，
当前标签页刷新后仍保留撤销入口。原始输入数据集不受影响。
底层将整个运行目录原子移动到 `frontend-runs/.trash/<运行编号>/`，不永久擦除文件；
删除后该记录的详情和下载入口不再可用，恢复后原始内容不变。
运行阶段尚未完成时也能导出已经保存的评分记录。
每次新建运行都重新采样，不自动复用历史评分。当前前端不提供失败重跑按钮。
原 CLI 的输出保持原位；左侧运行记录仅列出本前端创建的实验。

同一服务一次运行一个实验批次，批次内按既有配置并行。
停止会终止本地后台进程并保留已完成的检查点；已发出的 API 请求仍可能计费。
关闭浏览器不会停止运行。终端按 Ctrl+C 会关闭服务并停止当前运行。
服务意外退出后，后台进程会检测父进程退出并结束；下次启动会将旧运行标记为中断，
不会自动发起付费重试。

可修改端口、输入根目录和历史目录：

```bash
python3 -m frontend --port 8766 --data-root /path/to/datasets --runs-root /path/to/runs
```

服务只监听本机 `127.0.0.1`，静态文件采用明确的文件白名单，不暴露项目文件夹或 `.env`。
写请求校验本地来源与页面会话 token。此版本用于个人本地评测，不提供公网部署或多用户登录。
